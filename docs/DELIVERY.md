## 主要修复

## Rulings I made

以下按作出顺序保存全部八项决策及判断错误的代价。

1. 沿用已批准的 Python 与原生 HTML/CSS/ES Modules，不改成 React/Vite。若不合适，代价是后续界面结构重整，不是数据丢失。
2. 暂名“镜序”，采用克制深色、青绿主色和琥珀色审看提示。尚无精确个人风格参考；若不合意，可改名称与样式。
3. 补上完整编辑器需要的分集剧本、创作备注、场景与素材 CRUD。若超出需求，代价是移除新增接口，不改旧生产系统。
4. 首版上传至新建私有仓库，不擅自授予公开再分发许可。若名称或可见性偏好不同，可另行调整；私有默认降低披露风险。
5. 任务 `succeeded` 只表示技术执行完成，素材仍需明确选片和审看，不能等同整集验收。若状态映射不当，代价是误导交付状态及 UI/API 修正。
6. 允许适配器任务最小修改 Worker，传递已观察的服务端失败及时间证据。若协议判断错误，代价是集成重做及状态修正；不绕过 GPU 队列。
7. 持久化真实选片的源片入点、出点与时间轴，用实际素材时长限制字幕，不用计划镜头预算代替。若接口不合适，代价是本地持久化与 API 重整，不涉及旧制作数据。
8. 最终修复引入的两项真实前端回归由原负责人集中修正，并只做受影响验证，不带已知重要缺陷交付。若范围判断不当，代价是额外本地核验时间，不是外部写入或数据损失。

- 本地验证、仓库上传和远端 CI 是不同证据；远端运行结论以 GitHub Actions 对应提交的记录为准。
