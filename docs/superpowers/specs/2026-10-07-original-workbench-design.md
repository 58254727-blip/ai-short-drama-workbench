# 独立原创短剧工作台｜首版规格

## 目标与边界

独立开发一个 Windows 本地制作工作台，减少模型往返、镜间等待和重复返工，不降低对白、人物及剧情连续性要求。

这不是火宝 fork。新实现者只收到功能需求、公开接口文档与虚构测试数据，不读取或复制火宝源码、文档、图标、样式或私有配置。界面、数据结构、接口、调度器与测试独立设计；第三方通用组件单独核对许可。

代码目录：`F:\OpenSource\duanju-workbench-original`。运行数据与待上传源码分开。现有两部剧、服务、GPU队列、素材和数据库不变，新系统不会自动接管它们。

## 首版六项能力

1. **编导与分镜工位**：编辑剧情、角色动机、场景目标、镜头起止状态、转场及对白；支持人工输入和结构化导入。文本模型走显式配置的兼容接口，无模型时仍可人工工作。不将当前 Codex 会话伪装成永久免费 API。
2. **分集与素材隔离**：作品、集、镜头明确关联；读写校验归属。对白原文和镜头版本可追溯；导入本地视频成为候选，不自动覆盖选片。
3. **持久任务队列**：SQLite保存进度，重开保留断点。GPU一个工作槽，CPU校核与后期有界并行，不让模型逐镜搬JSON或反复轮询。
4. **本地H3适配**：使用已安装的本地ComfyUI服务，工作流和地址显式配置；不打包模型权重、不升级驱动、不启动第二套生产服务。没有兼容工作流时报告阻塞，不假称生成成功。
5. **素材复用与质量记录**：保存源哈希、参数和版本；合格选片冻结。错误分类为人物、动作、连续性、文字、声音；同类失败两次后改变方案，不无限重试。
6. **对白、字幕与拼接**：批量离线识别提供漏词、数字、否定词和额外话语线索，不能代替人工听审。字幕按实际音频可编辑对齐，FFmpeg后期及整集拼接保留待审状态，不用静态或重复帧凑时长。

## 架构提议

- 本地Python API服务、SQLite持久队列、浏览器工作台；默认仅监听回环地址。
- GPU执行已准备好的任务，CPU同时处理上一批识别、字幕与后期。
- 状态区分待准备、已就绪、排队、运行、候选待审、选片、失败；选片不等于整集或正式发布验收。
- 模型、工作流、FFmpeg路径是适配器配置，不写死盘符、作品ID、演员、模型名或端口。
- 重启先核验外部运行任务，不重复提交；错误信息必须可定位。

## 完整度与质量补充（用户要求：尽量好、尽量全）

- 首版闭环包含作品/分集、剧情与对白、角色/场景/道具资产、镜头版本、生成队列、选片与退回、声音校核、字幕时间轴、剪辑与整集导出。
- 角色参考图、声线参考和道具资产可导入并版本锁定，明确素材权利记录，不自动换脸或覆盖原参考。
- 编导工位记录每场目标、人物选择、因果、转场和下集期待；模型建议是候选，需要采纳后才更新当前稿。新增对白不得悄悄改变原句或说话人。
- 数据有导出/备份/恢复能力；恢复冲突必须明确反馈，不覆盖当前选片、锁定版本或其他作品。
- 工作台界面中文为主，需可编辑、可预览、可追溯、有错误与空状态；不接受只展示进度的空壳界面。
- 耗时拆成排队、准备、GPU执行、声音校核、后期及人工待审，基于实际时间戳，不把轮询次数或任务数量当产出。
- 能力没有配置时显示真实缺项，测试替身只能出现在测试中；未实现的操作不得伪造成功。

## 暂不做

用户系统、收费平台、团队协作、手机客户端、公开网站部署、自动发布、保证爆火。首版不迁移或重做当前两部剧，不占用其队列，不使用新收费API或购买服务。

## 验收

- 跨作品/跨集写入被拒绝，原数据不变。
- GPU最多一个任务，CPU后期可独立推进；程序重启不丢断点、不重复生成。
- 虚构素材贯通导入、候选选择、字幕编辑、拼接、解码检查。
- H3实测先确认旧队列空闲且用户同意，不影响已有制作。
- 源码不含私人剧本、演员、音轨、媒体、数据库、推理日志、密钥或本机配置。
- 未做真实生成、听审、画面审看的项明确列出，不以文本或解码测试冒充成片验收。
